# Note style coach (PR #38)

## What it does
- Turns an example note into a reusable note style. In **Note Styles** (or the style menu on a session summary) the user starts the coach, pastes an example or picks a built-in sample (Narrative, DAP, SOAP, Brief CBT), answers up to a few multiple-choice questions about anything unclear, and reads a fictional practice note written in the new style.
- The user can ask for changes in their own words (for example "Make it shorter"). The coach shows the old and new practice notes and asks which version to keep. Then the user names and saves the style, optionally using it for the next notes.
- Coach-made styles show "Made with the coach" in Note Styles and can be reopened with **Adjust**. Editing the text of a coach-made style by hand detaches it from the coach (`NoteStyles.svelte` passes `detachCoach`; no confirmation), and it becomes an ordinary custom style.
- The style menu uses a per-style **Show in style menu** checkbox instead of stars (stored in the existing `starred` column).
- The coach blocks the main window while open. It is unavailable while recording, while a summary or other job is running, when the license has ended, and when summaries are downloading, unsupported, or failed to load. Practice notes are fictional and never become sessions.

## How it works
- **Data flow** (`src-tauri/src/coach/commands.rs`): `coach_open` creates one in-memory `Draft` (only one at a time) -> `coach_build` reads the example into a `StyleSpec` -> `coach_answer` resolves each uncertain item -> `coach_practice` writes the first practice note -> `coach_interpret` turns a change request into a patch, writes a new practice note, and holds it as a proposal -> `coach_choose` keeps or drops the proposal -> `coach_save` stores the style. `coach_cancel` drops the draft. The example text and draft are not persisted; only the saved style is.
- **Rust modules** (`src-tauri/src/coach/`): `spec.rs` (`StyleSpec`, validation, `compile`), `extract.rs` (example -> spec, built-in samples, questions), `interpret.rs` (change request -> `Patch`), `practice.rs` (output checks, correction text), `commands.rs` (Tauri commands, availability, discard), `mod.rs` (types and events).
- **Deterministic extract and compile.** `extract::extract` reads headings, sentence counts per section, quote use, pronouns, and voice with plain text rules; no model is called. Only known layout labels (`HEADINGS`) become sections, so a name before a colon is not copied into the style. Items it cannot decide become `Uncertain` questions (layout, length, quotes, required sections, pronouns, voice). `spec::compile` turns the validated `StyleSpec` into prompt text: a grounding rule, the headings (required or optional), sentence and quote limits, pronoun and voice rules, and any focus areas. No example text is copied into the compiled style.
- **Change requests are not model-interpreted (differs from the spec).** `interpret::interpret` matches the request with keyword and number rules and returns a `Patch` (`Length`, `Quotes`, `Emphasis`, `Section`), a clarifying question, or `Unsupported` with `SUGGESTIONS`. `Patch::apply` produces a new `StyleSpec` and a plain-language change description. Requests are 1 to 500 characters (`validate_reply`). The model is used only to write practice notes.
- **Practice, checks, retry.** `coach_practice` and `coach_interpret` enqueue a `PracticeJob` (`src-tauri/src/jobs/queue.rs`: `enqueue_practice`, `run_practice`, `PracticeRun`) on the same job queue and summary model as real summaries, against the fixed fictional transcript `coach/samples/practice.txt` (up to `NOTE_TOKENS` = 512 tokens). After each attempt `practice::check` tests the output against the spec: sections present, no repeats, optional sections omitted, length, exact quotes, quote attribution, no names, pronouns, no preamble (`Check`). On a failure the next attempt appends the matching `Check::correction` lines. After at most `MAX_ATTEMPTS` = 3 attempts the best-scoring note (most passed checks) is returned, even if some checks failed; the result carries the failed checks. A model error or cancel returns "I couldn't write the practice note. Try again."
- **Save and visibility.** `coach_save` calls `Store::save_coach_style` (`src-tauri/src/store/prompts.rs`) inside `JobQueue::while_real_idle`, in one transaction. A new style is inserted with `starred = 1` (shown in the style menu); an Adjust updates the original row and fails with "This style changed. Reopen it before adjusting." if the row changed since it was opened. `use_next` also makes it the active style. Adjust (`coach_open` with a style id) uses the original compiled text as the base for the first practice note and requires an accepted change before saving.
- **Discard rules.** Starting a recording (`src-tauri/src/commands.rs`), losing license access (`refresh_availability`), or closing the window discards the draft and cancels the practice job (`CoachCancelReason`). A summary model that goes unavailable mid-practice cancels the job and returns an error result.
- **Commands** (registered in `src-tauri/src/lib.rs`; wrappers in `src/lib/api.ts`): `get_coach_availability`, `coach_samples`, `coach_open`, `coach_build`, `coach_answer`, `coach_practice`, `coach_interpret`, `coach_choose`, `coach_save`, `coach_cancel`.
- **Events** (`src-tauri/src/coach/mod.rs`, sent to the `main` window): `coach-availability`, `coach-progress` (attempt number), `coach-result` (practice note or error for a job), `coach-cancelled` (with reason).
- **Frontend** (`src/lib/components/`): `NoteStyleCoach.svelte` (the three-step sheet), `NoteStyles.svelte` and `NoteStyleEditor.svelte` (list, visibility, Adjust, detach), `CoachEntry.svelte` (entry button and unavailable reason, also used in `SummaryPanel.svelte`). Shared state lives in `src/lib/coach-context.ts`; example handling in `src/lib/coach-example.ts`.

## Config and data
- Column `prompts.style_spec TEXT` (nullable JSON of `StyleSpec`), added by migration `v8_style_spec`, schema version 8 (`src-tauri/src/store/migrations.rs`). Built-in and hand-written styles have `NULL`. `StyleSpec.compiler_version` is `COMPILER_VERSION` = 1; unsupported versions are rejected.
- Example note: 100 to 12,000 characters, plain text only (`extract::validate_example`).
- Compiled style: at most `MAX_PROMPT_CHARS` = 8,000 characters (`src-tauri/src/store/prompts.rs`), enforced in `compile`; the same cap applies to hand-edited styles.
- Spec limits (`spec::validate`): at least one required section; sentence range within 1 to 10; up to 6 quotes (a required quote needs at least 1); section headings unique, 1 to 60 characters, starting with a letter, using letters, numbers, spaces, or `- / & ( )`; each focus (`ClientExperience`, `Interventions`, `NextSteps`) at most once.
- Style name: 1 to 100 characters, no control characters. Change request or answer: 1 to 500 characters.
- A hand edit that changes the text of a coach-made style sets `style_spec` to `NULL` (`edit_prompt`, requires `detach_coach`); an unchanged text keeps it.

## How to test
- Rust: `cargo test --manifest-path src-tauri/Cargo.toml --features fake-engines` (coach unit tests in `src-tauri/src/coach/`, store tests in `store/prompts.rs`, queue tests in `src-tauri/src/jobs/queue_coach_tests.rs`).
- Frontend: `npm run check && npm test` (`src/lib/components/note-style-coach.svelte.test.ts`, `src/lib/coach-example.test.ts`).
- Native: `tools/uitest/scenarios/note-style-coach.uitest` (DAP sample -> questions -> practice note -> two change requests -> keep old / use new -> save). Run it as in `CLAUDE.md` "E2E / uitest": `swift run --package-path tools/uitest uitest note-style-coach --app <path to Scribular.app>`. Real-model practice notes are slow in the VM, so run it against the host llama-server as in `docs/remote-llm-uitest.md`: build a debug app with `--features remote-llm` and run with `SCRIBULAR_LLM_URL=http://192.168.64.1:5801` and `SCRIBULAR_SKIP_LICENSE=1` set in uitest's environment (the license skip works in debug builds only, `src-tauri/src/license/mod.rs`; `launch` forwards it, `tools/uitest/Sources/uitest/AppLifecycle.swift`). Assert fixed UI text, not model wording.

## Known limits
- Straight single quotes are ambiguous for plural possessives inside quoted dialogue (for example `'the clients' goals'`): `quote_ranges` treats an apostrophe as part of a word only when it follows a letter or digit and, inside a quote, is followed by one, so an apostrophe after a plural `s` inside single-quoted speech can be read as the closing quote. Not verified beyond the `quote_ranges` unit tests.
- Change requests only understand the patterns in `interpret.rs` (length, quotes, focus, add/remove/optional section); anything else returns suggestions.
- If all 3 attempts fail a check, the best attempt is still shown; the user judges it. `NOTE_TOKENS` = 512 can truncate very long styles (shortcut noted in `practice.rs`).
- AS1 (sheet blocks the main window; tray/menu-bar interruption) cannot be driven by the current uitest harness and stays manual.
- AS15 (a non-technical therapist completes the coach on a supported Mac with real-model timing) is future manual product testing; it has not been run.
- Only one draft can be open, and the coach cannot run while any real summary job is running.
