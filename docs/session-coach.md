# Session Coach, PR1 backend (no UI yet)

## What it does
- Revises a finished session note on request, for writing form only (length, quotes, sections, bullets). The Coach returns a full candidate note or a short reply. A candidate is held in memory; nothing is written to the session or the store.
- Requests outside length, quotes and sections get a fixed reply ("I can change length, quotes and sections. Ask for one of those changes.") without calling the model.
- Unavailable while recording, when the license has ended, while real summaries are queued or running, and when summaries are downloading, unsupported, or failed to load. Same reasons and messages as the note style coach (`CoachBlock`).
- PR1 ships the backend and typed IPC only. There is no screen that calls it (see Known limits).

## How it works
- **Commands** (`src-tauri/src/coach/session.rs`, registered in `src-tauri/src/lib.rs`; wrappers in `src/lib/api.ts`):
  - `session_coach_start(session_id, request, prior_requests, prior_candidate_id)` returns an opaque `job_id` and the result arrives later as an event. `sessionCoachStart` subscribes to both events before invoking, so no result is missed, and unsubscribes if the call fails.
  - `session_coach_stop(job_id)` cancels that job. A different or finished `job_id` is a no-op.
- **Start checks, in order:** main window only; the `remote-llm` build refuses when `SCRIBULAR_LLM_URL` is set ("Session Coach requires the on-device model."); request non-empty and at most 2,000 bytes, at most 10 prior requests of at most 2,000 bytes each; runs inside `Recorder::while_not_recording`; `commands::available` must pass; the session must exist, be `Done`, and have a non-empty summary; only one Coach job at a time ("The coach is still working. Try again."); `prior_candidate_id` must match the held candidate for the same session.
- **Queue** (`src-tauri/src/jobs/queue.rs`): `enqueue_session_coach` takes a `SessionCoachJob` (prompt, cancel flag, completion callback). It is refused when any real summary is running or pending (`CoachBlock::Busy`), when a practice or Coach job already exists, or when the model is not ready. The worker runs it only when no real summary is pending, so real summaries always go first. `run_session_coach` loads the summary model if needed, rejects a prompt that does not fit the context ("This session is too long for the coach."), and generates up to 512 tokens.
- **Prompt:** saved note, transcript, earlier requests, the earlier candidate (for follow-ups) and the current request. The model must keep every clinical fact and attribution, reuse only source spans, return the whole note with no preamble, and end with `<<END_OF_NOTE>>`.
- **Completeness check:** output without the `<<END_OF_NOTE>>` suffix is treated as truncated and rejected; the marker is stripped from the candidate.
- **Grounding and exact-quote checks** (`grounded`): every sentence-like span of the output (split on newline, `.`, `!`, `?`; compared as lowercase words) must equal a span of the saved note or the transcript, so new facts and recombined claims are rejected. Every quoted string in the output (`extract::quotes`) must appear verbatim in the note or transcript. Failure returns the reply "I couldn't revise that note. Try again." and no candidate. Known shortcut: safe paraphrases are also rejected.
- **Result events** (sent to `main`): `session-coach://result` with `SessionCoachResult { jobId, sessionId, outcome }`, where `outcome` is `{ kind: "candidate", candidateId, note }` or `{ kind: "reply", message }`; `session-coach://stopped` with `{ jobId, sessionId }`. A result is dropped if its job was cancelled or replaced, so a late result never reaches the UI.
- **Cancellation:** `session_coach_stop`, starting a recording, queueing a real summary (`JobEvents::session_coach_cancelled`, `recording_starting` in `src-tauri/src/commands.rs`), and an availability change (`cancel_for_gate`) all set the cancel flag, drop the queued job, abort a running generation, and emit `stopped`. Recording is not delayed by a running Coach job.
- **Availability gating:** `coach::commands::available` and `refresh_availability` cover the table in `CoachBlock` (`recording`, `accessDenied`, `busy`, `downloading`, `unsupported`, `loadFailed`); losing access cancels a running Coach job.
- **Privacy:** note, transcript and requests are held in memory only and sent only to the local model. The candidate is kept until replaced and is never persisted. Job and candidate ids come from `commands::opaque_id`. Error and reply strings are fixed text, with no note content.
- **Types** (generated by ts-rs into `src/lib/types/`): `CoachBlock`, `CoachAvailability`, `SessionCoachResult`, `SessionCoachOutcome`, `SessionCoachStopped`.

## Config and data
- No migration, no new columns, no settings. The saved session row is never changed by the Coach.
- Limits: request and each prior request at most 2,000 bytes; at most 10 prior requests; generation at most 512 tokens (`run_session_coach`); one Coach job and one held candidate at a time.
- State is `SessionCoach` (managed as `Arc<SessionCoach>`): the active job (`job_id`, `session_id`, cancel flag) and the last candidate (`session_id`, `candidate_id`, note text). Both are lost on restart.

## How to test
- Rust: `cd src-tauri && cargo test --lib` (grounding and exact-quote cases in `coach/session.rs`; queue cases in `jobs/queue_coach_tests.rs`: `session_coach_job_leaves_saved_session_unchanged`, `session_coach_completion_signals_availability`, `cancelled_session_coach_drops_late_result`, `real_summary_preempts_running_session_coach`; availability cases in `coach/mod.rs`).
- Frontend: `npm test` (`src/lib/api.test.ts` checks the listen-before-invoke order and the `session_coach_start` arguments) and `npm run check` (type check of the generated types).
- Native: none for PR1, because there is no UI.

## Known limits
- No UI until PR2. Nothing in the app calls `sessionCoachStart` yet.
- PR2 (per `plans/2026-11-16-session-coach-spec.md`): note-view conversation, full-candidate comparison, Stop, guarded acceptance with Undo/Redo, Copy integration and availability states (AS1, AS3 to AS6, AS10). The backend does not yet accept a candidate: no store write and no stale-base check exist.
- PR3: style derivation from accepted edits, preview, custom or built-in save, the one-time offer, and the real-model and privacy walkthrough (AS7 to AS9, AS11).
- Grounding is span-level: paraphrases that are safe are rejected, and a candidate can fail even when it is correct. Claim-level validation is a future upgrade.
- Support detection is a keyword list (`supported`: short, brief, long, quote, section, bullet and variants); other phrasings get the fixed reply.
- Oversized sessions are rejected rather than chunked. Not run against a real model; Fake-engine tests in `src-tauri/src/jobs/queue_coach_tests.rs` check that sentinel note content does not reach logs, diagnostics or telemetry, and that the saved note is unchanged.
