## Checks and spike evidence

- Rust crates: exact `=1.13.8` pins, Apache-2.0; extracted crate manifests and `build.rs` inspected. The Rust embedding API and real model inference compiled successfully on macOS arm64.
- Build script: macOS uses the official versioned release asset and `tar` extraction. It accepts `SHERPA_ONNX_ARCHIVE_DIR`; release CI downloads the asset explicitly, checks the recorded SHA-256, and passes that directory to Cargo. The inspected `zip` extraction branch is used for iOS, not this macOS target.
- Native shared asset: `https://github.com/k2-fsa/sherpa-onnx/releases/download/v1.13.8/sherpa-onnx-v1.13.8-osx-arm64-shared-lib.tar.bz2`; observed SHA-256 `ae77050cdae565496059d96f5ab33d77b397a0864282a4e4a26e3b3b3effb948`. This is a repeatability check of the downloaded bytes, not independent authentication. Extracted macOS arm64 libraries total about 31 MiB: sherpa C API 4 MiB, ONNX Runtime 27 MiB, C++ API 176 KiB. The official sherpa release page lists v1.13.8 and its publisher: https://github.com/k2-fsa/sherpa-onnx/releases/tag/v1.13.8.
- Model: `3dspeaker_speech_campplus_sv_zh_en_16k-common_advanced.onnx`, 28,281,164 bytes, Apache-2.0; source URL uses upstream's misspelled `speaker-recongition-models` release tag. SHA-256 `aa3cfc16963a10586a9393f5035d6d6b57e98d358b347f80c2a30bf4f00ceba2` matches the checked-in Electron copy and the upstream model mirror's recorded checksum; it is not an independent authenticity proof. ModelScope's CAM++ model card lists Apache License 2.0: https://www.modelscope.cn/models/iic/speech_campplus_sv_zh-cn_16k-common.
- Real-engine run: `src-tauri/tests/fixtures/audio/2-speakers-12s.wav`, 16 kHz mono, 12 seconds. The Rust candidate emitted six finite 192-dimensional embeddings. Apple arm64 local run: 202 ms warm model load, 98 ms inference, 105 MiB maximum resident set. This is an inference smoke/performance measurement, not an accuracy or speaker-label benchmark.
- Electron comparison: unavailable. `sherpa-onnx-node` and its native package are not installed in the local Electron checkout, and no fixed cross-engine clip corpus exists. No cosine parity or accuracy result is claimed.
- RustSec: `cargo-audit --no-fetch --stale` scanned the feature lockfile (523 crates). It reported four `zip 2.6.1` advisories (RUSTSEC-2026-0429, -0367, -0368, -0369); the affected `ZipArchive::extract` path is iOS-only in the inspected build script, while this feature's macOS build uses tar. It also reported warnings for `proc-macro-error` (unmaintained) and `glib` (unsound iterator); the glib dependency is Linux-only in this macOS target. The initial scan found Tokio 1.53.2's I/O safety advisory; the lockfile now uses patched Tokio 1.53.3. The audit command exits nonzero because of the zip advisories.

## Integration boundary

Use shared dynamic libraries so macOS signing can bundle and verify both `libsherpa-onnx-c-api.dylib` and `libonnxruntime.dylib`. Runtime model inference is CPU-only. The speaker model remains optional and downloads only when requested. If the Electron baseline, real-user recording, long-session performance or signed/notarized release cannot be observed in this build phase, record that honestly in verification; do not infer results from the fixture smoke run.
